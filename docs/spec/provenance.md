# Provenance envelope

## Protected header

Every envelope is a compact JWS with a protected header containing exactly the
security-relevant key material:

```json
{
  "typ": "ubag-provenance+jwt",
  "alg": "EdDSA",
  "jwk": {"kty": "OKP", "crv": "Ed25519", "x": "..."}
}
```

`kid` MAY be present as a routing hint. When present it MUST equal the
`ubag:sha256:` reference derived from the JWK that verified the signature.
It is never an identity input. The authoritative agent reference and registry
lookup key are always derived from the verified JWK. A carried JWK cannot
override a registered key.

Unprotected JWS headers are forbidden. Duplicate JSON members, invalid UTF-8,
non-I-JSON values, unsupported critical headers, and conflicting
representations MUST be rejected.

## Payload

```json
{
  "jti": "single-use-client-generated-id",
  "htm": "POST",
  "htu": "https://service.example/payments",
  "iat": 1785000000,
  "exp": 1785000060,
  "ath": "base64url-sha256-of-presented-credential",
  "ubag_qsh": "base64url-sha256-of-origin-form",
  "ubag_content_digest": "sha-256=:base64-value:",
  "nonce": "optional-server-issued-nonce"
}
```

Rules:

- `jti` is generated by the client and is single-use. It is not a server nonce.
  Its UTF-8 representation MUST be between 1 and 128 bytes.
- `nonce` is present only when the server issued one.
- `htm` is the uppercase HTTP method.
- `htu` is the canonical public absolute URI without query or fragment.
- `ubag_qsh` is `BASE64URL(SHA-256(origin-form bytes))`. Origin-form is the
  exact public `:path` value, including the query when present. It MUST NOT be
  parsed, sorted, percent-decoded, re-encoded, or Unicode-normalized.
- `ubag_content_digest` is the exact normalized RFC 9530 `Content-Digest`
  field value for the raw HTTP content bytes. The field is signed by being a
  payload claim; an unsigned HTTP digest is insufficient.
- `ath` is required when a credential is presented and is the base64url
  SHA-256 digest of its exact bytes. It MUST be absent—not null or empty—when
  no credential is presented.
- `exp - iat` MUST be between 1 and 60 seconds. A verifier permits at most five
  seconds of clock skew.
- Numeric claims MUST be integers in the interoperable range
  `0..9007199254740991`. Floating-point JSON numbers are forbidden.

The profile uses ordinary compact JWS signing input with both protected header
and payload encoded using RFC 8785 JCS. A verifier checks the signature over the
received bytes and requires both decoded components to equal their JCS encoding.
Non-canonical or duplicate-member JSON is rejected even when its signature is
otherwise valid.

Retries always require a fresh envelope and new `jti`. A failed transport
attempt does not make an envelope reusable.
